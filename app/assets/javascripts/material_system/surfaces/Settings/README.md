# Settings surface adapter

The Settings surface follows `design/Settings.dc.html` for layout, control anatomy, and states. The design file is reference data and is not a production data source.

## Host contract

Mount `Settings.vue` with an `adapter` object (the `settingsAdapter` prop remains a compatibility alias). The object must implement all methods exported as `SETTINGS_ADAPTER_METHODS`:

- `load()` returns the current project snapshot.
- `updateProject(changes)` persists project fields and returns the resulting snapshot.
- `updateLogo(file)` validates and persists a local avatar file, then returns the resulting snapshot.
- `updateMemberRole({ id, role })`, `removeMembers(ids)`, `createVariable(payload)`, `revealVariable(id)`, `removeVariables(ids)`, `unprotectBranches(ids)`, `toggleIntegration({ id, on })`, and `bulkToggleIntegrations({ ids, on })` call the existing project stores, GraphQL mutations, or Rails endpoints and return the resulting snapshot.

The adapter owns authentication, permissions, server-side validation, and error mapping. A rejected request must throw; the surface keeps its prior state and shows the error through the non-blocking notification channel. An adapter response may include `errors`, which are rendered as a truthful status message.

## Snapshot shape

Snapshots may use the normalized fields (`projectName`, `visibility`, `members`, `variables`, `protectedBranches`, and `integrations`) or the existing GitLab response names. `normalizeSettingsState` accepts both forms and rejects records without stable IDs. Variable values are discarded during normalization unless the adapter explicitly marks the record `revealed`; ordinary loads should provide only a server mask.

When no adapter is connected, the surface renders empty states and a visible unavailable status. It never supplies project names, member identities, branch rules, integrations, or secret-like values from fixtures.

## Rails endpoint helper

`createRailsSettingsAdapter` adapts host-provided endpoint URLs and the page CSRF token to the contract. The host must provide URLs generated by Rails view helpers; the helper does not guess routes. It uses same-origin credentials, checks every HTTP response, and propagates validation failures without applying a local optimistic mutation.
